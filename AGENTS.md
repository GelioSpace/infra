# AGENTS.md

NixOS flake for Gelio's servers. Currently one node, `geliofront`: a Hetzner VPS
running Docker containers behind a host-level Caddy reverse proxy.

## Layout

- `flake.nix`: builds one `nixosConfigurations.<name>` per directory in `nodes/`,
  plus an `installer` ISO config. `nodeMeta` exposes each node's metadata
  (used by `toss.nu` and `ci/deploy.sh`).
- `nodes/<name>/`
  - `configuration.nix`: the node; imports modules with relative paths (`../../modules/…`).
  - `hardware-configuration.nix`, `networking.nix`: generated by nixos-infect. Don't touch unless asked.
  - `host-metadata.nix`: `system`, `host` (SSH address), `hostKey` (pinned SSH host key),
    optional `port`, `user`, `mode` (`"rpi"` selects the nixos-raspberrypi builder).
- `modules/`
  - `core.nix`: base for every machine (Lix, nix settings, shell, packages); imports `barecore.nix` and `options.nix`.
  - `barecore.nix`: minimal shared settings; imports `ssh-keys.nix`.
  - `ssh-keys.nix`: all root SSH keys (owner, another admin, and the `Gelioinfra` CI deploy key).
  - `docker.nix`: Docker daemon config.
  - `imperative-caddy.nix`: Caddy with a hand-edited Caddyfile (see below).
  - `network-server.nix`: sysctl and limits tuning (BBR, buffers, backlogs, conntrack).
  - `home-manager/`: only used by the installer.
- `ci/deploy.sh` + `.github/workflows/deploy.yml`: CI deploys (see below).
- `toss.nu`: the owner's manual deploy tool (Nushell). Leave it alone unless asked.
- `secrets/`: git-ignored; synced to `/secrets` on hosts by `toss.nu`. Never commit or print contents.

## Working on it

- The flake only sees files tracked by git: `git add` new files before evaluating.
- Check a node evaluates:
  `nix eval .#nixosConfigurations.<node>.config.system.build.toplevel.drvPath`
- Inspect an option: `nix eval --json .#nixosConfigurations.<node>.config.<option>`
- `nix flake check` currently fails on `packages.x86_64-linux.installer`
  (`system.build.iso` should be `system.build.isoImage`). Known, left as is on purpose.
- Lint shell with shellcheck and workflows with actionlint
  (`nix run --inputs-from . nixpkgs#shellcheck -- ci/deploy.sh`).
- Keep the existing style: sparse comments explaining *why*, no mass reformatting.
- Don't deploy, SSH into hosts, or push without the owner asking.

## Things that already bit us

- **Node imports must stay relative paths.** `flake.nix` builds node module paths by path
  concatenation (`dir + "/configuration.nix"`), which is what keeps `../../modules`
  inside the flake source. Interpolating (`"${dir}/…"`) copies the node dir to the
  store alone and breaks relative imports.
- **Caddy config is imperative by design.** The Caddyfile lives at
  `/var/lib/caddy/Caddyfile`, edited on the server, applied with `systemctl reload caddy`.
  Rebuilds never touch or reload it. Don't move it into Nix or `virtualHosts`.
  tmpfiles only seeds a comment-only placeholder (caddy rejects an empty Caddyfile).
- **Docker's userland proxy must stay enabled.** Ports published without an address
  default to `[::1]` (`ip` and `default-network-opts` in `docker.nix`), and only
  `docker-proxy` can forward host IPv6 to IPv4-only containers. With it disabled, those
  bindings are silently dropped. Disabling it also broke Caddy → `127.0.0.1:port` before.
- **Upstreams in the Caddyfile:** use explicit `127.0.0.1:port` / `[::1]:port`, matching how
  the container publishes; `localhost` tries `::1` first.
- **Changing Docker network defaults** needs `docker compose down && up -d` per project
  (networks keep options from creation time); `liveRestore` keeps old containers running
  through daemon restarts.
- **`network-server.nix` values are `mkDefault`.** Don't add limits the kernel/NixOS
  already set higher (file-max, nr_open, inotify, max_map_count); a NixOS default at the same
  priority also causes a conflict error.
- **SSH keys:** each key once, all in `ssh-keys.nix` (imported by `barecore.nix`, so every machine gets them).
  Removing the `Gelioinfra` key breaks CI deploys.
- **The servers run Lix**, whose experimental feature is `pipe-operator` (singular);
  CppNix on dev machines and CI uses `pipe-operators`.

## CI deploys

- Push to `master` (or manual dispatch) deploys every node; PRs only build.
- Needs the `SSH_PRIVKEY_INFRA` repo secret. The host key is pinned via `hostKey`.
- `ci/deploy.sh <node>` builds on the runner, copies the closure, then:
  1. arms a transient `systemd-run` timer (`nixos-deploy-rollback`, `ROLLBACK_TIMEOUT`,
     default 300s) that switches back to the current boot generation;
  2. activates with `nixos-rebuild test` (boot entry untouched, so a hard reboot also
     returns to the old system);
  3. checks a fresh SSH login, rolls back immediately if activation failed;
  4. disarms the timer and runs `nixos-rebuild boot`.
- Runs locally too, inside `nix shell --inputs-from . nixpkgs#nixos-rebuild-ng`,
  using your own SSH keys when `SSH_PRIVKEY_INFRA` is unset.
- In the workflow, Nix must get `experimental-features = nix-command flakes …`;
  the "ignoring untrusted flake configuration" warnings are expected.
- In shell steps, assign `$(…)` to a variable first: a failure inside
  `echo "…$(cmd)"` is swallowed even under `set -e`.
